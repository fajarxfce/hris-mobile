# Bounded account history discovery

Global incoming recovery visits one history locator per worker turn. The account storage reader previously applied that logical limit to raw published checkpoints before filtering internal projections. A page of notifications, room bindings or queue metadata could therefore occupy multiple empty worker turns after actual Company content had already drained. Native worker5 established that only global history discovery remained; it did not expose the exact remaining partition sequence.

The account reader now requests one bounded page of at most 17 raw checkpoints, the existing maximum. The mapper validates every observed row, consumes at most 16, returns at most the requested number of meaningful history locators, and stops before another unreturned locator. It skips roots, browse history and internal projections without treating them as incoming work. The continuation identifies the last consumed raw row; an unconsumed lookahead always retains continuation. Empty raw pages and true EOF complete normally.

For Company history, six notification partitions and later Space history, a limit-one read returns the Company locator and advances past the six metadata partitions. A second read after closing/reopening storage returns the Space locator and EOF. A full page of internal metadata still returns bounded empty progress, and the seventeenth row remains for the next read.

The repository owns raw metadata acquisition and technical exception mapping; its mapper owns storage-shape validation and cursor translation. Existing use cases retain admission, selection, actual content/key reads, queue progress and completion. Company-only and Space-only readers are unchanged. There is no schema, worker-turn limit, timer, SDK or UI change.

Tests-only reproduction failed exactly eight intended cases on unchanged production. The corrected reader passes all 113 targeted desktop/Android/browser cases. Full validation accepts 14,555 cases: 4,784 fresh, 21 source-exact proof cases and 9,750 unchanged dependency-verified cases. Full check, Android host/release/lint, Wasm, iOS metadata, proof APK/unit, format/architecture/detekt pass. One mapper method name changes with its contract; all other predecessor identities remain.

Native worker6 now passes first-page content, completion within the unchanged four-turn limit, empty demand and Company EOF before the final covered-head request. That final request creates new Published work and fails the no-op assertion because its use case still checks Space rather than Company history. This independently confirms the next root cause; final repeat equality and offline worker reopen remain unreached. Same-boot read-only inspection proves recovery complete, zero physical/inventory work and one newly queued Published task. No active HTTP/storage failure, source mutation, compiler overlap or phone interaction. Full native/product acceptance remains open.
