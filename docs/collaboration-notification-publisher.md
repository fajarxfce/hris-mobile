# Admitted native publication coordinator

`CollaborationNotificationPublisher` connects the existing projection, encrypted journal,
validation and settlement operations within a finite application surface lease. The
application graph provides a parameterized factory; the host supplies its already-started
surface owner. This does not start native delivery or install a receiver. Chat push stays
off until ongoing invalidation, callbacks and retained-input review are usable.

The call accepts a processed native parent, opaque candidate IDs and generic localized
copy. It constructs the captured company scope internally. Preview text comes only from
admitted retained originals, never from a push body. Preparation checks owned company,
DM, original, identity, settings and read facts. Issuance durably retains the exact
Prepared render and authenticated action envelopes before any OS submission.

Within the owner's nonwaiting ten-second cooperative request budget, the coordinator
validates before submission, again after native acknowledgment, then settles Published
by exact journal CAS and validates the resulting revision. Failure or cancellation
propagates to the owner, which joins pending work and compensates attempted exact native
references. A lost storage response may leave Prepared or Published committed; subsequent
work reuses that render and its envelopes. No implicit send, network acquisition, retry
loop or distributed OS/database transaction is introduced. The result contains only an
outcome enum, never private preview/action content.

## Presentation and actions

Hidden previews use only generic localized title/body. Sender-only previews add the
admitted name; Message previews may add the admitted bounded body. The raw adapter still
constructs a generic public lock-screen version independently.

Issuance now reports whether this call confirmed retention of a new original. Reusing
an existing render or replacing only source stamps, privacy or native family is silent.
A lost issuance response followed by recovery is also silent. Publication defaults to
silent even for a new original; the acquisition caller must explicitly allow an alert,
and issuance must independently report a new original. This trades a possible missed
sound after uncertainty for avoiding repeated alerts. It is not exactly-once alerting
or an initial-sync/backfill policy; candidate admission remains a host responsibility.

The five raw routing hints carry the four existing authenticated journal actions.
Open aliases the Reply target envelope for navigation only. A future native host must
authenticate it, match the exact card/render, and navigate without invoking a send or
mark-read command. The mapper does not implement that host routing. Other actions retain
their exact stored envelopes; no resealing occurs during publication or replay.

## Outcomes and remaining integration

Permission-required, channel-disabled and capacity outcomes preserve Prepared for an
explicit future recovery. Pending history, a suppressed candidate or an older/inactive
watermark performs no OS submission and does not remove a different existing card.
Ongoing active-card invalidation must independently handle company denial, read/mute/
redaction, changed privacy and focused threads. In particular, merely publishing another
suppressed candidate is insufficient to clear a previously displayed card. Opaque
discovery/retirement must preserve exact watermarks without exposing denied preview data.

Ten application integration tests resolve the actual Koin factory and feature use cases,
use encrypted SQLite across container reopen, and acquire fictional originals through
the existing HTTP/simulated-SDK fixture. The OS surface is a deliberate fake. They cover
write-before-submit, retained envelopes, silent replay, all preview modes, native
permission outcomes, lost native/storage acknowledgment, pending cancellation, parent
replacement and denial/privacy change during submission. Seventeen domain issuance cases
include new-original versus replay/native-family alert behavior.

[Recorded checks](measurements/chat-notification-publisher-2026-11-03.json) distinguish
these tests from native SDK IPC. Android/iOS host binding, real notification-input process
death, old-family/pre-retention review, foreground scope and all-company invalidation
remain required. No user-phone installation or full communications acceptance is implied.
