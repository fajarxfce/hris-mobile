# Owned recipient contact labels

The recipient thread observes the exact local peer contact through the existing directory use
case. It needs no canonical conversation, directory inventory, API request or transport setup.
The collector owns admission, current-session checks, denial retention and cancellation. Public
company labels are captured before a suspending guard, and foreign/malformed peers are rejected.
Credential age alone does not hide owned data. Normal session renewal does not restart the read.

One typed contact result joins the recipient's existing request generation. Success updates only
the contact; it does not rebuild message rows or replace the serial editor. Transient failures
retain the admitted name without replacing the message list. Explicit removal clears the name.
A closing denial retires the whole request, fences late source results and clears private state.
The navigation entry supplies the owned name to the existing state-only page.

Before association there is one exact contact subscription per recipient model. After association
the canonical participant observer owns another: two bounded local subscriptions, released with
their owners. No repository singleton cache, guessed metadata or extra full-directory read was
introduced. Existing whole-directory observation keeps its previous behavior.

editor identity, late results, disposal and the explicit post-association subscription bound.
