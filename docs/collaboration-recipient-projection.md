# Local recipient draft and original projection

The recipient projection repository observes an exact draft and authenticated source-version marker under one published checkpoint. It reads the bounded original inventory only when that logical source version changes. Each observation retains immutable decoded originals for its selected peer; typing changes the draft without reloading or decrypting all pending originals. The cache is scoped to the collector and cleared on failure, disappearance, cancellation or replacement. It does not keep keys or UI state. An account change is checked by the raw store and by the admitted domain observer.

The initial inventory is limited to the existing 128-original quota plus one lookahead; exceeding the quota fails rather than truncating a thread. Originals are validated across the bounded source, filtered to the exact recipient and ordered by immutable submission time and ID. The existing marker format distinguishes typing from source changes, includes generation identity and preserves old missing-marker partitions through their existing upgrade path. A newer inventory checkpoint cannot be combined with an older draft frame; the owned header observer supplies the next coherent publication without a timer or transport retry.

Raw header lists are copied before cipher suspension. The one-shot inventory is copied inside its flow before first() cancels the producer, so an adapter releasing mutable buffers in finally cannot erase captured messages. The extra conflate before header capture was removed during review; datasource invalidation already owns update coalescing. Failed records keep the public storage failure classification and a later valid update can recover.

ObserveCollaborationSpaceRecipientProjection checks current local account/Group ownership before and after reading, copies the bounded result before its final guard, and retains confirmed denial until new observed admission. Account replacement, source completion and disposal close obsolete readers. Existing admission policies remain in domain; the repository only coordinates raw storage and mapping. Generated application DI resolves the repository/use-case binding without starting native or network work.

This projection contains local originals before canonical transfer; it is not yet a complete product thread.
