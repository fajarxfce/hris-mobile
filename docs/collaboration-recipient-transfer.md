# Finite recipient transfer

A captured recipient submission can now move into its canonical conversation without
clearing another editor or inventing a new message identity. One domain operation owns
the five-second attempt. It coordinates the source outbox, canonical command ledger,
conversation metadata, inbox acknowledgement and current local admission. No transport,
native device, HTTP provisioning, worker or screen is started by this operation.

The exact command ID pins the destination. An existing authenticated recipient proof
wins over newly acquired peer metadata, including when another writer won a different
canonical target. Both participant accounts must match the captured sender/recipient.
Missing metadata returns a waiting outcome and keeps the source. An absent source cannot
authorize a new insertion. Storage replies alone cannot confirm transfer: uncertain
insertion is followed by exact command readback.

The existing inbox producer continues to own index writes. Transfer constructs the
existing seed policy's proposal and probes with `seed(repair = null)`, which cannot write
or request repair. A missing index returns WaitingForInbox; mismatched snapshots have
at most three reads. Only semantic RETAINED acknowledgement permits source retirement.
Independent canonical drafts and previously edited, hidden or confirmed anchors keep
their existing policy. A cancelled canonical original is retained proof, not a new send.

Source retirement compares the complete immutable submission. Its repository authenticates
the bounded source and checkpoint, then commits one tombstone and the next encrypted
checkpoint under the raw store's account/revision compare-and-set. Three conflicts stop
the attempt. Later recipient typing, other originals and the current wake are unchanged.
A missing content key fails without generating a replacement. A lost deletion reply is
confirmed only by exact source absence; an unreadable or still-retained source is not success.
Admission and cancellation remain checked around each asynchronous boundary.

Regression coverage includes competing canonical proposals and source removers, lost replies,
false-success adapters, missing metadata/index, finite conflicts/timeouts, account replacement,
denial, cancellation before/after commit, restart, key loss and tampered encrypted frames.
The actual application DI container resolves the new operation. Desktop and browser execute
the new common cases; Apple source compilation is separate from runtime acceptance.
