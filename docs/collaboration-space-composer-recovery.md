# Bounded organization composer recovery

A retained send gesture now recovers locally before native device or key prerequisites.
Each five-second pass attempts at most eight originals, advancing an encrypted Group cursor
before each attempt. It confirms the exact immutable message before retiring that original;
unknown metadata or changed content leaves the original held for review. New typing stays in
its independent editor slot. Company cursor bytes remain unchanged and Group namespaces stay
separate, with independent legacy ciphertext and cross-platform storage contracts.

Recovery reports pending submissions and pending native messages separately. Empty outbox
storage cannot erase a queued message's recovery wake. If native prerequisites are absent,
either kind keeps the wake with scheduler backoff. Transient local publication failures still
allow separately admitted existing native messages to drain; bounded continuation then backs
off instead of immediately scheduling itself. Authority failures and cancellation stop the
attempt. A current validated empty inventory and exact wake generation authorize completion.

The owning use cases coordinate typed repositories and admission policy. Repositories own
encrypted datasource I/O and conditional storage, while the application worker coordinates
local and native results. No new HTTP polling, UI state in repositories, usecase-to-usecase
calls, provider transaction replacement or selected HR company dependency is introduced.

Focused 169 and full 15,014 checks pass, preserving all 14,911 previous case identities and
adding 103 JVM/browser/Android executions. Coverage includes lost replies, cursor fairness,
capacity, interrupted retirement, missing keys, retained queued commands, malformed inventory,
late account/Group changes and cancellation. The 44 new shared Apple methods still require
actual hosted execution; Linux executes zero Apple tests. Android release compilation/lint,
shared Wasm/iOS compilation, proof assembly and native test-source compilation pass.

Two original/Group native delivery scenarios pass on the final proof with the pinned SDK8,
a fresh 2560 MiB two-core emulator and no concurrent compilation. They preserve original
transactions through lost projection/acknowledgement and an offline recipient. These are
existing queued-message delivery scenarios; a new composer UI submission is not claimed.
The emulator was stopped after the run. No phone installation, Group live rollout or measured
UI latency is claimed by this increment.
