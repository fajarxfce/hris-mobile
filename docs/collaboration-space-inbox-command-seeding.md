then prepares a local activity without constructing a send or editor successor. Existing edited,
hidden or confirmed anchors keep their text, delivery state and immutable position. New activity
uses retained original/conversation time and the index insertion counter; it cannot inherit a
newer row's timestamp. Independent draft state remains unchanged. Actual Company originals are
not relabeled as Group commands, and edit commands have a separate contract.

The seed repository returns an explicit outcome. A null repair proposal only probes the exact
index/reference state: RETAINED confirms a semantic replay before progress acquisition, while
DEMAND_REQUIRED changes neither index nor progress. An empty index probe creates no keys. The
admitted caller prepares a fresh repair Request only for new work. Index/reference and request
then share the existing two-partition ReplicaStore mutation. CHANGED permits a fresh observation,
limited to three attempts with one demand identity. Operational failure stops; cancellation and
current account/Group admission surround each I/O. Existing history keys cannot be recreated over
retained ciphertext. An exact or completed replay preserves later repair progress.

idle, then seeds its previously absent reference. The new atomic demand triggers completion even
though the command inventory is empty. Independent draft, completed reference and repair progress
survive reopening; an exact replay creates no further work. No native client is opened or message
sent. Nine shared storage methods cover empty probing, joint persistence, completed replay,
competing index/progress writers, lost replies, cancellation, missing keys and continuous observers.
