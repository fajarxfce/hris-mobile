# Inbox edit outcomes from exact provider evidence

Pure policies now distinguish an observed or rejected replacement from an unobserved pending edit.
They admit the exact Group/Company command, original target, retained publication/body/time and
trusted provider sender/operation/hash. Missing or unstamped commands, queue absence and an ordinary
send acknowledgement do not prove the edit was applied. Contradictory redaction facts fail instead
of combining different history versions. Hidden/deleted preview content is never restored by policy.

A separate successor policy can establish that one later local action is already visible. The
caller first admits the pending command and performs exact completion reads for both applicable
namespaces. Exactly one authenticated completion must match the visible operation, sender, hash,
body, retained alias, target and physical room. Ambiguous or absent matches remain unresolved.
Only local authored timestamps are compared; provider time cannot order local gestures.

Twenty-three shared methods cover actual namespaces, exact/missing/unstamped facts, all128aliases,
129overflow, changed pending pointers/body/markers, original identity, redaction, completions,
foreign accounts/rooms and provider timestamps earlier than local actions. Focused41/full16765 pass,
including every16719 prior case and46 new JVM/browser executions. Actual Apple execution is separate.

These policies do not publish a projection, create receipts, retire commands or schedule delivery.
The admitted producer must combine current access, canonical coherent history/evidence snapshots,
exact command lookups and bounded index reads, then condition publication on source/index revisions.
Incoming completion, unresolved handoff, finite catalog/binding backfill and product activation
remain required. This is HRIS policy with no Starter port.
