# Admitted history inbox publication

PublishCollaborationSpaceInboxHistory publishes up to sixteen captured local history references
under current account/Group admission. It reads the canonical physical Group or actual Company
source, exact original and pending command facts, coherent replacement evidence, and both
applicable successor completion namespaces. Repositories own acquisition/mapping; the use case
owns finite contention preparation and policy. No native transport or UI state enters this path.

The result partitions every requested alias into confirmed retained and unresolved references.
Unknown originals remain durable work for the caller. Lost publication responses remain failures;
a later invocation can confirm a no-op. Publication checks the original source and index revisions,
so a newer local edit or source update cannot be overwritten by a previously prepared proposal.

All possible physical/Group/Company anchor identities are checked before allocation. A retained
original whose command proof is absent stays unresolved instead of becoming a duplicate History
row. Sixteen legacy originals need at most48 keys in two batches of32 under one index version.
Duplicate identity is rejected. Detached input/snapshot/candidate/anchor lists remain stable
through suspension. Existing position/time, drafts, pending text and confirmed delivery survive.
Confirmed denial is latched; cancellation joins in-flight acquisition; ordinary storage failure
never enters the three-preparation contention loop.

Twenty-two shared behavior methods cover physical namespaces, unresolved aliases, missing proof,
two-batch index races, lost replies, exact no-op, provider/successor outcomes, newer local edits,
mutable inputs, malformed snapshots, bounded contention, storage failure, denial and cancellation.
