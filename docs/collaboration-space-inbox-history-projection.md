# Bounded history publication proposal

One pure policy prepares at most sixteen coherent original changes for the canonical inbox.
Existing physical History anchors survive later command proof; duplicate anchors remain an
error. New ambiguous originals return explicit unresolved IDs without allocating an activity.
The caller must retain their durable work even after publishing the resolved part of a batch.

Updates preserve original position/time, independent draft, optimistic edit text and confirmed
delivery. A PENDING association cannot downgrade SENT/FAILED; a confirmed original ACK may
upgrade delivery. Clearing an edit requires its exact admitted pointer. Hidden/deleted content
stays hidden/deleted. Sixteen hidden changes retain the seventeenth visible fallback candidate.

Source owners still supply current access, complete original/command/edit proof, all queried
anchors and up to seventeen visible candidates under coherent source/index revisions. The
proposal neither acquires data nor writes a transaction, schedules work or activates a UI.
Its temporary batch state ends with the synchronous call and returned lists are detached.

Sixteen shared methods exercise actual Group/Company coordinates, late identity proof, local
edit retention/clearance, stale pointers, original target/room changes, draft/fallback behavior,
hiding/redaction, incomplete identities, malformed sources, duplicate anchors, index conflicts,
maximum batch, ordinal overflow and caller mutation. Focused57/full16797 preserve all16765 prior
identities plus32 JVM/browser executions. Apple compilation passes; actual execution is separate.
This HRIS policy has no Starter port. Admitted source and incoming/backfill owner integration
remain required before product graph, thread/list or phone acceptance.
