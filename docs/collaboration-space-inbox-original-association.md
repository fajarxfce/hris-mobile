# Original identity for inbox history

A retained incoming original can describe an existing Group or Company command before the
independent command observer sees its acknowledgement. Two pure domain overloads match an
admitted immutable room binding, command owner/conversation, physical room, original sender,
logical ID and canonical complete content. Plain text or UUID equality alone is insufficient.
The Company overload retains the actual Company/conversation coordinates from the canonical
binding; Group originals retain their Group namespace. A valid ID in two namespaces does not
make them interchangeable.

The result contains the original source, captured send time and actual command delivery state.
Staging and Staged remain PENDING; Sent is server acknowledgement only. Identifying the original
through another retained alias does not require the acknowledged alias in this snapshot and
never creates or settles a receipt. Hidden/redacted originals and admitted edits retain their
original identity without changing stored content or visibility. Edit commands are excluded.
Malformed/foreign storage facts fail; valid nonmatching facts return null. Missing-origin legacy
records do not acquire proof from an event ID. Null does not authorize allocating a new History
anchor: the source owner still needs to resolve the other actual namespace and ambiguous legacy
records. A producer must also preserve newer delivery state when its command read is stale.

Eighteen shared policy methods pass on JVM/browser: focused 28/full 16,479, retaining all 16,443
prior identities. Actual new Apple execution remains separate from compilation. This is one
part of the admitted incoming producer. Preview precedence for pending edits, source/index
publication, Company-history adapters, finite repair and product ownership still precede
activation. No SDK call, polling queue, phone update or live rollout is introduced.
