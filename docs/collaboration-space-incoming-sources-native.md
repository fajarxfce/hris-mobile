# Native incoming receipt acceptance

The SDK8 callback now has an Android proof through the actual application incoming-source owner and encrypted demand repository. One real write is held and committed while its reply is reported lost. The native acknowledgement independently verifies the exact retained receipt. Two foreground resumptions keep one receipt write, one acknowledgement and the same native instance. A separate offline process reads the identical durable receipt and history without acquiring a runtime.

Six native controls passed on a fresh 2560 MiB, two-core emulator in 274.319 seconds, with no compiler overlap or phone interaction. The receipt case made 32 Matrix requests and 13 native API requests; the [measurement](measurements/collaboration-space-incoming-sources-native-2026-11-12.json) includes exact operation counts, source/APK hashes and report identities. The proof uses SDK 26.10.23-hris.8. This does not describe the delivered phone release89, which still uses SDK6.

At this earlier checkpoint, the complete seven-case worker suite was not accepted. It subsequently
passed after the [Original covered-hint correction](collaboration-original-covered-hints.md), and
[eight native cases now include real late-key retention](collaboration-native-late-keys.md). Its pre-existing registered-worker fixture omits process incoming collection; a separate read-only diagnostic confirmed an installed source with no durable source progress and `WaitingForOriginalSource` from canonical routing. The failed package and userdata are retained. Four later cases in the initial run were prevented from starting by that protection, and the six unaffected controls were subsequently run in isolation.

The worker fixture must use actual source collection and synchronization and validate Company-owned history after canonical LEGACY conversion. Review also found that Original incoming waits for provider EOF before reading content. Progressive content and the revised worker acceptance are tracked separately; neither the empty-repeat nor content-before-EOF assertions may be removed to conceal these gaps. Late keys during a held application write, replacement accounts, long quiet request counts and the Apple native adapter remain additional acceptance work.
