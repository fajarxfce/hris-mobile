# Recover one retained Space history page

Space history uses its retained logical conversation, traversal device and provider.
These coordinates remain distinct from the currently registered physical Matrix
device, including when a Space room aliases an Original company conversation.
An alias does not authorize reading or acknowledging the Company history lane.

The reader admits the current account, native session, source, exact room binding
and registration. It confirms one coalesced recovery request through local readback
and reads at most sixteen references. Provider identity must survive readback and
page acquisition. An absent history stays absent; a completed generation does not
restart. Expired preparation does not hide owned local references. The operation
has a five-second cancellable lifetime and performs no primary seek or key probe.

The existing content acquisition owner accepts a separately typed historical page.
It checks exact scoped original and replacement facts before reading Matrix. Local
facts avoid native reads and rewrites; unknown sources use the existing content
pipeline. Shared target reads and retained changes are deduplicated, source identity
is checked against captured references, and results preserve source order. Actual
native owner, device, room and joined/encrypted state must match registration.
The historical lane does not fetch transport, join, sync, send or provision keys.
Its fifteen-second lifetime and denial cleanup remain owned by one invocation.
The primary API keeps its transport contract and existing native-session alias case.

Completion accepts only results bound to the exact captured page, runtime and
history. It calls the existing Space recovery transaction once, with binding,
registration, source and account checks around the write. Retained or explicitly
unsupported sources resolve; missing keys and targets remain unresolved. A true
reply identifies only the attempted generation, counts and cursor. A false, lost,
cancelled or stale-owner reply is not a receipt, and a null cursor is not account
completion. Bounded mutable input lists are copied before suspension.

The three new common suites contain 19 reader, 34 acquisition and 35 completion
cases. Focused controls retain the 25 primary acquisition cases, 26 history-loader
cases, 12 primary reference cases, eight primary policy cases, 56 real recovery
storage cases, 26 room-binding storage cases and both DI resolution orders.
Planned focused execution is 243 JVM plus 241 browser cases. Full acceptance must
preserve all previous identities and reach 13,598 local cases on 5,067 source inputs.

No application consumer or native listener is activated here. Bounded account
service, primary EOF demotion with an atomic wake, key-change receipts and listener
cancellation/drain, and blocked-history liveness remain required before activation.
