# Canonical incoming handoff for legacy aliases

A retained Published LEGACY alias identifies an original Company conversation. The incoming worker
now resolves that alias before using the Published provider path. A local overload on the existing
binding resolver owns queue capture, source/registration admission and immutable Original metadata.
True SPACE work keeps its Published path, while typed Original work uses its accepted application
turn. No additional client, scheduled task, usecase-to-usecase dependency or remote lookup is added.

An eligible alias is replaced atomically with a new UUID Original task at its existing FIFO position.
The new task starts Latest with the same known or unknown head and the actual registered physical
source. Its retry is reset for the new operation. Old Space phases, provider cursors and Group device
identities never become Company history; existing local facts remain untouched. Both Original
metadata indexes must be confirmed before the queue changes.

Source progress must already carry a genuine sync position. If missing, the alias remains waiting
until a real batch is retained. Another unfinished Original task preserves both requirements, even
when head IDs match or are unknown. Waiting outcomes enter the existing domain backoff owner;
successful pagination keeps its existing immediate continuation semantics. The application uses
the same worker mutex, parent lifetime and forty-second room deadline. The local resolver has one
five-second deadline including index retention and queue confirmation.

Current source, full registration, account/native ownership, alias identity and known denial remain
checked around suspended I/O. A write reply alone cannot prove conversion. Exact readback requires
the new Original task and removal of the old alias generation. A later producer alias is independent.
Known CAS contention preserves current work. Source positions, inventory loss, rescan and the
independent wake survive the handoff; no queue write is replayed inline.
