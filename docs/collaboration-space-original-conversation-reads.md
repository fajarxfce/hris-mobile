# Owning original conversation metadata acquisition

ReadCollaborationSpaceOriginalConversations owns one explicit page or exact original
metadata request. It coordinates the original repository with the existing finite
native metadata lifetime, current account/native parent and organization-denial state.
No selected HR company is needed; original company/conversation coordinates stay intact.

Requests and completed results must satisfy the original metadata policies, even when
a repository returns a typed value. A terminal page stays terminal and schedules no
poll or follow-up. Late results cannot escape account replacement, original hard
expiry, wall-clock rollback, monotonic timeout or a newly confirmed admission denial.

Confirmed server denials remain retained through caller cancellation and failed
persistence. An explicit successful metadata recovery may inspect an original
conversation while leaving its previously denied directory closed. It never publishes
an encrypted projection, opens an SDK queue, creates an acknowledgement or authorizes
sending. Those owning flows must separately establish current admission and exact
immutable message mappings.

The focused gate passed18 cases in3 suites; the full root/Android/browser gate passed
5,498 fresh cases in645 suites with4,314 unchanged inputs, zero failures/errors/skips,
Android lint or Detekt findings. Nine new cases cover request/result validation,
account replacement, original hard expiry, wall rollback, monotonic bounds, cancellation,
late success, retained denial after failed persistence and isolated page ownership.
