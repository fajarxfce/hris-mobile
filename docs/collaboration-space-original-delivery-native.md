# Original messages after organization handover

The real Android SDK6 experiment passes in135.232s, including a fresh isolated emulator
boot. Two fictional messages are staged through actual application use cases and encrypted
storage. Their original SDK queue remains paused until their native accounts/devices and
existing encrypted room are adopted through real native HTTP and provisioning/room workers.
The original company room publication itself is the existing explicit SQL fixture.

Recipient readiness is a deliberate precondition: the fixture reads the signed public
identity produced by the actual SDK, checks its original fingerprint, then submits the
same identity through the current organization gateway keys/upload. It creates no private
keys and writes no key-publication rows directly. This does **not** prove automatic Mobile
first-key-publication activation. Both SDKs are closed before this setup; the receiving SDK
stays closed throughout outgoing delivery and recovery.

The Mobile proof uses the actual existing-only runtime, room-binding preparation and
`DeliverCollaborationSpaceOriginalMessages`. A test-only repository delegate interrupts
before Staged-to-Sent CAS, after the durable application acknowledgement is verified.
The driver kills exactly that proof PID, preserves its SDK/AppDB/Keystore and restarts
with a new local owner. Both original transactions/content/device coordinates survive.
No replacement command is enqueued. Both records become Sent, and the provider contains
exactly one encrypted event per original. Each journal contains its matching event only.
A third process reads both Sent records before any transport after the owned reverse is
removed. Actual assertions cover the native bootstrap/room/pair/readiness and original
physical Matrix device, not just a domain fake.

Ten native application requests occur across the two delivery invocations: exactly two
bootstrap replays and two direct-transport reads. No native registration, room request or
failed native request occurs during those invocations. This is one bounded fixture, not a
latency percentile or a claim that all Matrix traffic has this count.
