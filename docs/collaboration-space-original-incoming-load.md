# Local incoming resolution preserves the original company and device

An original Company chat cannot use the Group registration receipt as its physical history device.
The local incoming loader now derives that Company/device from the exact current registered LEGACY
provenance, matched to the installed Matrix source, before returning historical room coordinates.
Published and original conversations with the same UUID remain separate targets.

The use case reads the captured queue generation and full task, current registration and immutable
original metadata, then rereads registration. Company, account participant, server and physical room
must agree; a valid registration for another Company cannot consume this task. Missing, pending or
unconfirmed registration never supplies replacement coordinates. Missing/newer work returns no old
task; conflicting facts in the same generation fail. The incoming traversal retains the original
device ID and existing Company history namespace. Its historical timestamps are unchanged.

Directory admission, current account/native parent and the exact installed source are checked around
each suspension. Confirmed denial wins over a late local failure. Cancellation propagates, and one
five-second local deadline bounds stalled reads without retries. Ordinary credential age and selected
HR Company do not hide owned historical facts. This local result grants no current content permission.

The pure domain policy validates registered provenance; the use case coordinates repository reads;
repositories keep their raw storage responsibility. The owning data module binds the use case and
the existing application DI test resolves it. No new API, transport check, Matrix client, sync
collector, provider page, queue write, wake or acknowledgement is started by this operation.
