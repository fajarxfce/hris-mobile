# Local Original history resolution for key recovery

A retained Company history locator can now resolve its exact room metadata without borrowing
a primary incoming task. The owning use case accepts explicit Company/conversation/device
coordinates and the installed source. Existing registration policy verifies the current
Original's Company, native session, provider and device identity. The locator's historical
device remains unchanged; it is not replaced by the current Original or Group device.

Only the account-owned Original metadata indexes are read. Company, conversation, participants
and provider server must match. Directory/session/native/source checks fence every suspension;
a final exact registration readback also fences an absent-metadata result. Missing metadata
returns `MetadataUnavailable`, which remains unresolved work. The existing Company list lacks
room/server identity, so it cannot serve as an inferred fallback. One five-second deadline
bounds the local operation; cancellation propagates and storage failures keep their classification.

Domain owns repository coordination and admission; the data module binds the constructor.
There is no usecase-to-usecase call, primary queue read, history mutation, key/provider request,
new native owner or collector. The returned coordinates do not grant live content access or
prove the current native client can decrypt an old device's retained references.

Validation includes24 new common domain cases and200 focused desktop/browser cases. Actual
encrypted Original-metadata18, Company-traversal18 and locator15 contracts per platform remain
controls, along with the existing Original incoming loader24 and application graph2. 12,796
full local cases passed with prior identities, source/library hashes and dependency closures
verified. An initial freeze bookkeeping command failed due to an unset state field; it changed
no source. The runner's independently captured initial manifest matched the subsequently
recorded candidate exactly, and remained unchanged throughout validation.

Space/LEGACY history resolution, durable key passes, exact primary demotion and stored-key
signals remain separate work. Raw observation and Original producer stay disabled. No native,
phone, Starter or live-server activation is implied; all54 PRD groups remain open.
