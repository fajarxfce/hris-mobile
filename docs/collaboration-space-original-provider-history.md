# Original incoming history uses its original device and Company cursor

An original chat cannot store pagination under the Group registration receipt. Its Matrix client,
physical device and Company history partition already have their own identity. The new owning use
case reads one bounded provider page through the installed Group runtime and retains the unchanged
physical page in that original Company traversal. It neither copies nor relabels saved Space frames.

The owner checks the full captured original task, installed source, registered LEGACY provenance,
immutable metadata, native session deadline and registry around suspended work. Original Company and
device come from the matching registration, never the selected HR Company or Group receipt. The page
must retain its exact local/native parent, account, Company, device, room and requested bounds. A late
source, registration, task or parent replacement rejects the result before it can advance history.

Latest or SavedPosition follows the captured phase. Shared domain transition rules retain provider
order, reference counts and pending seek. Only a finished wave promotes its head to the next exclusive
boundary. Existing Published policy keeps its Group-device and non-null provider checks; original
Company progress keeps provider=null. A saved exhausted position makes no provider request or write.

The existing Group Matrix gateway already authorizes original rooms around each content request.
This owner therefore adds no direct-transport or metadata HTTP request, SDK acquisition, sync startup,
incoming queue mutation, wake or content acknowledgement. One invocation has a 15-second deadline and
at most20 provider references. Current denial is retained even if restriction cleanup fails; the owned
runtime closes without rolling back already committed historical facts. Cancellation propagates.

Successful atomic storage is checked against its exact resulting progress. A false CAS never becomes
an acknowledgement. If a Storage failure loses the commit reply, the owner can confirm that same
checkpoint and every expected event through at most20 indexed source reads. Missing, different or
concurrently changed evidence preserves failure; it never resubmits the page during that invocation.
An empty EOF can be confirmed without inventing reference reads. Content and queue completion remain
separate owning operations.
