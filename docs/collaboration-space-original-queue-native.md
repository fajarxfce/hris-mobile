# Original paused transactions across organization adoption

The isolated Android proof creates two paused transactions through the application's
existing queue owner and immutable Matrix SDK4. A synthetic loopback server supplies
one encrypted room and empty account data. It never accepts a room join, message send,
queue settlement or delivery acknowledgement. No employee or real provider is used.

The proof records the complete original transaction IDs, logical IDs, serialized
content, sender, content hash and physical device/bootstrap provenance. It then uses
the actual protected-record handover and cancels adoption immediately after committing
the schema4 record. The original keys and pending queue remain on disk.

The driver closes the HTTP listener and removes its owned ADB reverse before stopping
the application. A different process restores only the existing SDK files. The
organization runtime rejects queue reads before publication and under another logical
owner, native parent, device or bootstrap. After publication, the original queue is
read offline and compared field by field, including the original physical identifiers.
An HR company switch or its access denial cannot replace that organization owner.
Closing and reopening the same adopted bootstrap preserves both the protected record
and the exact paused transactions. Legacy queue acquisition stays excluded.

The driver requires the dedicated emulator, an absent isolated debug proof package,
an explicit ABI and the immutable SDK4 native-library hash. It never installs over an
existing package. Success removes its fixture and verifies absence. Failure retains
the owned app data for inspection while closing the listener and removing its reverse.
The local wrapper stops its exact emulator and verifies process/transport absence.
Failed native attempts use separate retained userdata images; subsequent attempts
never overwrite them or the original Bima device.

The seed bounds request sizes/counts, joins request handlers on shutdown and records
only fixed endpoint categories. The synthetic account has no global account-data
events, so an exact-user GET receives Matrix404 M_NOT_FOUND. Other users, malformed
paths and writes remain rejected. A nonzero unexpected-request count fails the proof.

records source checks, each native ABI and the retained failed attempts. Both ABI CI
jobs now run the proof before notifications and archive its bounded results. This
establishes original paused-queue continuity only. Matching immutable application
commands, live delivery, logical conversation/history publication, new-parent recovery,
product activation and physical-phone latency remain separate acceptance work.
