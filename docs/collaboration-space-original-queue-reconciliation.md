# Match original SDK transactions with immutable application commands

The original queue read coordinates current native setup admission, the exact original
conversation and selected legacy identity, a paused runtime snapshot, and point lookups
of immutable message/completion records. It needs no selected HR company. Original
company, conversation, device, native family and bootstrap coordinates remain separate
from the current logical organization owner and bootstrap operation.

The pure preflight validates the complete bounded snapshot before exposing its logical
IDs for storage lookups. Every SDK original must match one application command by logical
ID, transaction ID, complete sender/content origin and physical device/room. The existing
captured-transaction policy permits historical bootstrap aliases only in the same physical
store; each record keeps its original device metadata. Unknown, missing, duplicate,
null-logical, malformed, queued, staging or cancelled originals reject the entire match.
There is no subset that can silently release an unmatched native transaction.

An already-sent original additionally needs its exact immutable completion, primary event
and bounded unique aliases. Duplicate events cannot confirm different commands. Empty
SDK inventory is only an empty local observation; it never proves server acceptance.
The result detaches repository collections and redacts its diagnostic string. Matching
neither changes a command, settles/resumes a queue, joins a room nor grants live delivery.

ReadCollaborationSpaceOriginalQueue uses the existing invocation-owned native setup
admission checks for this adoption-recovery step. It rejects an already-denied directory
before metadata/private reads and checks admission after every suspension. Original hard
expiry, wall-clock rollback, monotonic budget, caller cancellation and obsolete runtime
withhold results. The metadata recovery read's permission to inspect while a directory
is denied is deliberately not used for private queue facts.

Only authenticated metadata HTTP denials persist an organization restriction and close
that exact logical runtime, even through caller cancellation or failed persistence/
cleanup. A native SDK credential rejection cannot masquerade as a server organization
denial. Existing encrypted facts and transaction identities are retained. The read has
a 15-second acquisition lifetime; runtime closure belongs to the existing resource owner.

The final focused gate passed 22 cases: ten pure policy cases, ten owning lifecycle
cases and two actual application DI cases. Full root, Android, browser, proof compilation,
lint and quality checks passed 5,538 fresh cases in 649 suites (512.73 seconds), with
4,320 unchanged inputs and no failures, errors, skips or Android lint findings.
The first policy gate passed its tests but Detekt rejected a 112-line method. Separating
the pure provenance/ID preflight needed before storage reads retained every guard;
the next policy gate and both final gates passed without suppression.
