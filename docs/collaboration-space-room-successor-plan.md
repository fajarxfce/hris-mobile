# Atomic original/successor storage design

Status: [storage implementation and exact validation](collaboration-space-room-successor.md) are locally accepted. [Current-native owning preparation](collaboration-space-room-preparation.md) is now locally accepted in its own slice. Dispatch/projection remain separate.

After owning Room resolution passes, use existing raw CommandStore.archiveAndInsert. No new DB migration or raw transaction abstraction is needed. Retain exact original request/state ciphertext and an authenticated successor link in its archive, while inserting one replacement Pending Room under the same conversation resource in one transaction. No intermediate free resource; shared capacity remains unchanged at128.

Extend Room command with optional immutable predecessor operation ID (default null), and command record with optional authenticated successor ID (default null). Old request schema1/outcomes1/AAD remain unchanged; only replacement Room requests use explicit new request schema2 containing predecessor. The record's successor is archive metadata, not a remote outcome. Fenced remains Fenced and never becomes a fake receipt.

A pure handoff policy requires validated unlinked original Fenced Room, validated replacement Room with a distinct ID and predecessor==original ID, same API/account/space/conversation/peer. Current native/device admission and allocation belong in the owning use case, not the repository. Do not use device wall-clock ordering as server non-execution evidence.

The repository must refuse independent insertion of a NEW predecessor-bearing Room. Exact lookup/replay of an already retained replacement remains allowed. Handoff compares the complete decoded expected active record, seals a separate successor-purpose link, and uses raw archiveAndInsert. Missing keys cannot regenerate over original/archived records. Decode old Recorded archives exactly as before; decode Fenced archives only with a valid authenticated successor link. Archived originals remain findable, absent from active observations, and cannot be reactivated. Every subsequent mutation of either terminal record is rejected.

Lost handoff response must recover the known original, validate its successor link and the successor's immutable predecessor without allocating another operation. Competing handoffs have exactly one successor, one archived original and no ghost record. The owning flow resolves at most bounded known links; no archive scans, unbounded chain walk, SDK/store reset, message-ID replacement or provider/content authority.

Use real SQLite/IndexedDB transactions and restart tests, capacity edge, competing handoff vs update/insertion, full ciphertext preservation, failed/cancelled/committed-but-lost return, current-account switch, malformed link/schema, wrong original/peer/account/space, key loss, legacy archives, and find/observe continuity. Android host/root/Browser actual case selection/sharedWasm and source Apple/native CI remain required. Update affected repository fakes explicitly; do not weaken the interface with a silent default implementation.
