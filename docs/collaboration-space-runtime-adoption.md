# Restore the original SDK as an organization runtime

`CollaborationSpaceRuntimeRepository` exposes logical organization ownership through
an unpublished application-owned lease. Android binds that contract to the existing
process repository and registry. It does not create another native SDK owner or
interpret the selected HR company as organization authority.

Installation requires a confirmed current-format bootstrap and the exact immutable
original handover. The original directory must already contain its regular lock,
cache directory, and nonempty state and crypto databases. Existing-only acquisition
never creates or repairs these files. Missing, corrupt, linked or busy storage fails
without substituting a new identity.

Under that original directory lease, the repository verifies the private account
against the original provider identity before staging credentials. The same acquisition
path restores the native client paused, verifies its actual identity again, persists
readiness, and transfers cleanup ownership to the registry. Credential callbacks
remain bound to the selected bootstrap namespace. Exact replay retains refreshed
credentials and does not rewrite the original response.

The returned lease stays unpublished until an owning use case revalidates current
native parent, organization admission, device and durable bootstrap. It exposes no
legacy message/history methods or raw SDK client. Every legacy repository lookup,
including bulk resource selection, excludes organization runtimes. HR company changes
and denials preserve organization ownership; exact organization closure and native
parent replacement retire it. Cleanup retains the original failure if disposal fails.

The two-ABI native proof uses the immutable SDK 4 and real Android Keystore. It cancels
after credential staging, kills the process, restores the original private identity,
checks unpublished ownership and HR independence, then reopens the same bootstrap
without another credential write. Its first run caught a legacy bulk-lookup bypass;
that failed fixture and unchanged assertion are retained. The corrected run passes
on x86_64 and ARM64. Only its own fixtures are removed.

[Validation](measurements/collaboration-space-runtime-adoption-2026-11-07.json) records
all attempts, source hashes, native results and local gates. This proof establishes
original keys and physical queue namespace continuity, not delivery of an actual old
pending transaction. No live product caller or organization activation is added.
The owning admission flow, stale-bootstrap races, changed-parent recovery and product
routing remain separate required work before activation.
