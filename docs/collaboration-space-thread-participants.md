# Local participants in an organization thread

The existing canonical thread observer now carries the exact conversation, peer labels,
selected provider identity and, for retained Original history, the self identity read from
that history's physical namespace. The selected provider may differ from the original
sender; neither room origin nor the selected HR company invents a sender ID.

The directory reads one indexed published contact. A bounded inventory of original native
registration records must agree on one immutable provider identity, including pending and
unconfirmed registration records. This metadata proves neither current device admission
nor possession of encryption keys. Foreign, malformed, duplicate or conflicting records
remain explicit failures. Contact company labels are captured before publication.

First successful publication carries actual local participant results with history.
Observed absence and failure remain distinct; they do not fabricate identity or erase
readable history. Known command/history failures still publish before participant reads
finish. There is no debounce or artificial delay. Bound
threads use the binding's canonical facts directly. An unresolved thread owns one finite
metadata read shared by its canonical facts and peer lookup. All reads remain inside the
existing account, Group admission and selected-binding child, with cancellation and joined
retirement. No API, native SDK, mutation, new local cache or retry is added.

Both bound and unresolved branches share one named cold canonical-command observation
inside that same owner. This removes duplicated repository observation, validation and
unread-source handling; it does not move policy into a helper layer. Dependency wiring
stays in the data module and participant selection/capture remains pure domain policy.

Sixteen new domain methods cover provenance, bounded inventories, changed labels, held
readers, early command failures, denial/logout, slow consumers and binding removal. Two
shared storage methods read actual encrypted registration, original identity and directory
records across renewed login and published contact changes. Focused 118 passes. Full 14,816
accepts 12,778 fresh and 2,038 exact unchanged cases, retaining all 14,780
prior identities with 36 new JVM/browser cases. Source checks, Android release compile/lint,
shared Wasm/iOS ARM64 compilation, domain/data native-test compilation and proof assembly pass.
